Lesson 003: Creating Your Own Module

Lesson 3 · MyOpenLab Module Architecture · Mission · Glossary · ← Lesson 2

One win for you

By the end of this lesson you can generate a working module skeleton from the IDE wizard, fill in its process() logic, compile it, and see it appear in the palette.

Path A: the IDE wizard (the fast route)

MyOpenLab ships a New Java Component wizard (src/VisualLogic/gui/DialogNewJavaComponentAssistent.java). It generates the whole folder structure for you — the same anatomy you studied in Lesson 2.

  1. Open the menu item that triggers jmniCreateNewJavaComponentActionPerformed (src/VisualLogic/gui/FrameMain.java:3733). Requires a JDK, not a plain JRE.
  2. Choose type: Circuit Element (logic) or Front Panel Element (GUI).
  3. Enter the name and the palette group (folder) to drop it into.
  4. Define pins per edge (top/right/bottom/left), each with a name, data type, and input/output.
  5. Optionally add properties (they become VS objects + property-editor rows).
  6. Press OK.

The wizard then (FrameMain.java:3746-3789):

compName/ ├── definition.def ← generated (ISDIRECTORY=FALSE, CLASSCIRCUIT=…, ICON=icon.gif) ├── icon.gif ← copied from compTemplate ├── src/ │ ├── make.bat ← copied; "javac -d ..\bin *.java" │ └── CompName.java ← generated skeleton └── bin/ ├── image.gif ← copied from compTemplate └── (your .class here after compiling)

It also refreshes the palette and opens the code editor. You'll get a reminder: "Don't forget to compile the new Element."

The generated skeleton

The wizard writes a complete JVSMain subclass via generateSrcFiles() (DialogNewJavaComponentAssistent.java:1672). Its shape should look familiar from Lesson 2:

public class CompName extends JVSMain { private Image image; // Properties, Inputs, Outputs — declared as VS* fields public void init() { initPins(top,right,bottom,left); // create pin slots initPinVisibility(t,r,b,l); setSize(30+w,30+h); image = element.jLoadImage(element.jGetSourcePath()+"image.gif"); setPin(0, ExternalIF.C_BOOLEAN, ExternalIF.PIN_INPUT); // per pin element.jSetResizable(false); } public void initInputPins() { input0 = (VSBoolean) element.getPinInputReference(0); // bind inputs } public void initOutputPins() { element.setPinOutputReference(0, output0); // register output } public void process() { } // ← YOUR LOGIC GOES HERE }

This is the same contract you traced in Lesson 2 — init() declares, initInputPins()/initOutputPins() bind references, process() reacts.

What you actually write

The generated skeleton is runnable but does nothing. Your job is three things:

// 1. In init(): declare pins, image, size // 2. In initOutputPins(): register your output VS objects // 3. In process(): read inputs, compute, push outputs

To push a value out, the pattern is (see GetFile.java:66-94,107-108):

out.setPin(0); // remember which pin this VS object belongs to out.setValue("hello"); // put data in element.addToProcesslist(out); // queue the wire → destination process() runs

To react to an input, check the changed flag (from Lesson 2):

if (input0 != null && input0.isChanged()) { boolean v = input0.getValue(); // …do something… }

Properties you add to the wizard appear in setPropertyEditor() as element.jAddPEItem(...) rows (Gatter3.java:109-115).

Compiling

Two ways, both need a JDK:

  • In the IDE: the code editor's Compile button → Tools.compileFile(...) (src/VisualLogic/Tools.java:156), which compiles to bin/ using the JDK's in-memory compiler.
  • By hand: run make.bat in src/ — it runs javac -d ..\bin *.java.

Compiled .class files land in bin/, where the Loader picks them up on next placement. Palette refresh already happened — drag your new element onto a canvas.
