Lesson 002: Anatomy of a Module

Lesson 2 · MyOpenLab Module Architecture · Mission · Glossary

One win for you

By the end of this lesson you can open any element's folder in distribution/Elements/, read its definition.def and its Java source, and explain what each piece is for.

A module is a folder

A MyOpenLab module (also called an element) is literally a directory. Take the Starter element as our specimen:

Starter/ ├── definition.def ← metadata the IDE reads ├── src/Starter.java ← the logic, in source ├── bin/ ← compiled classes the Loader picks up └── bin/icon.png ← palette icon

Real example: distribution/Elements/CircuitElements/Extras/Starter/

definition.def — the module's ID card

The IDE discovers elements by walking folders and parsing definition.def as KEY = value lines. Two keys decide everything:

ISDIRECTORY = FALSE ← TRUE means "category folder", recurse in CAPTION = Starter ← shown in the palette (localized variants exist) classCircuit = Starter ← Java class to load at runtime Icon = bin/icon.png

The parser is src/VisualLogic/Tools.java:641. Every key you may see — classfront, claspath, vm, redirect, resizesynchron — is written/read there.

The Java side: extend JVSMain

The class named by classCircuit extends JVSMain. When the element is placed on a canvas, the wrapper Element (src/VisualLogic/Element.java:653) does this:

1. Loader builds a URLClassLoader over bin/ 2. Class.forName(...).newInstance() Loader.java:41-45 3. classRef.beforeInit(args) 4. classRef.xsetExternalIF(this) → element = externalIF; init();

Step 4 is the handshake. Your module gets a public field element of type ExternalIF — a giant interface that lets your logic control the wrapper (set pins, sizes, captions, load images). src/tools/JVSMain.java:30, src/tools/JVSMain.java:194.

The lifecycle methods you override

Look at Starter.java — it overrides four things:

init() → declare pins, size, icon initInputPins() → bind VS fields to pin references process() → react when data arrives paint(Graphics g) → draw the element onDispose() → free resources

Inside init() the pins are declared. initPins(top, right, bottom, left) creates pins in four regions; setPin(i, type, io) gives each a data type and direction:

initPins(0, 0, 0, 3); // 3 pins, all on the left edge setPin(0, ExternalIF.C_STRING, element.PIN_INPUT); setPin(1, ExternalIF.C_STRING, element.PIN_INPUT); setPin(2, ExternalIF.C_BOOLEAN, element.PIN_INPUT);

Then initInputPins() grabs the live references:

inApplication = (VSString) element.getPinInputReference(0); inRun = (VSBoolean) element.getPinInputReference(1);

distribution/Elements/CircuitElements/Extras/Starter/Starter.java:60-105

The crucial mental model

Key Concept: process() runs on the destination element, every time a wire delivers new data to it. A module does not poll — it gets called. The VM keeps a queue (processList) of wires that have data; it pops one and calls the destination's xonProcess() (= process()). See src/VisualLogic/VMObject.java:1781 and :1843.

That is why Starter's process() checks inRun.isChanged() — only act when the boolean actually changed, not on every cycle.
