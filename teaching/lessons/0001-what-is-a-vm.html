Lesson 001: What is a VM?

Lesson 1 of 10 · MyOpenLab GUI/Dashboard Course · Mission

The Core Concept

Every MyOpenLab project is built around a VM (Virtual Machine). Despite the name, this isn't a Java VM or CPU emulator — it's a visual canvas where you place and connect programming blocks.

Key Concept: A VM is a workspace containing elements (blocks) connected by wires. Each VM can be either a Circuit (logic) or a Front Panel (UI).

Circuit vs Front Panel

MyOpenLab has two types of VMs:

┌─────────────────────────────────────┐ │ CIRCUIT VM (Logic) │ │ │ │ [Timer] ──wire──▶ [Counter] ──▶ [LED] │ │ │ │ Elements process data │ │ Wires carry values between pins │ └─────────────────────────────────────┘ ┌─────────────────────────────────────┐ │ FRONT PANEL VM (UI) │ │ │ │ ┌──────────┐ ┌──────────┐ │ │ │ Slider │ │ Display │ │ │ │ (input) │──│ (output) │ │ │ └──────────┘ └──────────┘ │ │ │ │ Elements are GUI widgets │ │ Users interact directly │ └─────────────────────────────────────┘

The Element

Every block in a VM is an Element. Elements have:

  • Pins — connection points (inputs on left, outputs on right)
  • Properties — configurable settings (color, size, range, etc.)
  • Code — Java behavior executed each simulation step
Front Panel Elements are GUI widgets users can interact with:
• Input: Sliders, buttons, text fields, combo boxes
• Output: Displays, LEDs, graphs, gauges, oscilloscopes

How Data Flows

Data flows through wires connecting element pins. When the simulation runs:

  1. Each element reads values from input pins
  2. Executes its code
  3. Writes results to output pins
  4. Values propagate through wires to next elements
